Quick primer: when a software or game company builds a product, they first write code — the original recipe. Then the source code is compiled into a binary — the finished cake. Consumers only ever see the binary. For decades, software companies relied on this gap: nobody could see the recipe, so copying or modifying software just by looking at the binary was extremely hard. AI changes everything: GPT-6 Astra can look at any software's binary and reverse-engineer it at >99% success, and the recently released Claude Opus 5.5 seems even better.

For example, AI has already fully decompiled Super Smash Bros., Mario Kart 64, Halo, Kingdom Hearts, and Fire Emblem — just a few examples. I won't teach you to crack Photoshop with AI — legal issues. Let's talk safer uses: game mods and mashups.

There are several approaches. The simple one: **pass-through mods** — like putting Minecraft into GTA. You don't rewrite either game from scratch. You keep both original games/systems and have the AI build a layer connecting them. Say a Minecraft player places TNT at some location; the mod layer translates that into something GTA understands — spawn an explosion object at that location — and when the TNT detonates, the mod tells GTA to trigger an explosion there. Think of it as a bridge converting actions and physics between two games. This requires both games running on your system at once. Another example: porting Spider-Man into a Batman game. Impressive-looking, but the most limited approach — you're still constrained by the original engines; it's two games taped together, and collisions/physics can glitch.

If you want to try it, there's good news: plenty of prebuilt tools/skills you can hand to an AI agent. A similar tool, **"reverse engineer anything,"** also ships prebuilt skills and an MCP the AI can connect to directly.

The second approach is much grander: **rebuild the software that runs the game**. Classic example: vanilla World of Warcraft — but your character rides a skateboard.
