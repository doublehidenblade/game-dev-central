# Watchdog prompt — prove dispatch or escalate

Read [EXECUTION_POLICY](../dispatch/EXECUTION_POLICY.md) and the
[coordinator prompt](COORDINATOR_PROMPT.md). These replace historical automatic
publication, browser-action handoffs and global reconciliation instructions for
this mechanism. Keep the current communication, inspector and queue safety rules.

Each pass, activate Game-development in every shell with fail-fast handling. Read
the authoritative [attempt journal](../dispatch/ATTEMPTS.json),
[ready queue](../dispatch/READY_QUEUE.md) and fresh exact candidate evidence.
Run [dispatch_loop.py](../watchdog/dispatch_loop.py) `cycle`; the existing
`coordinator-plan`/`dispatch-guard` remain read-only evidence gates. Do not run the
legacy loop, drain `state/pending_actions.json`, use `push_code.py`, or claim a
planner launched a worker.

For every candidate, reconcile current board rows, open PRs and explicit user
stops **before selection**. Preserve unknown attempt counts and session liveness.
When an authorized coordinator receives `DISPATCH_REQUIRED`, it persists the
reservation, rechecks the exact guard, launches through its authorized tools and
records the actual session and first code/artifact write. Admission or a session
without a write is not implementation. The watchdog itself does not implement games.

After ten minutes without the complete receipt, the attempt is unsuccessful.
Reconcile the exact launch request/session before replacement. Keep live/unknown
reservations; never nudge or duplicate a working session. Move to another independently
eligible approved scope with nonconflicting executor/writes. One initial attempt
plus one evidence-based correction is the maximum, including historical attempts;
no new task alias, model, source head or failure label resets it.

If the queue is empty, report `ESCALATION_REQUIRED` and the exact per-candidate
blockers/receipt links returned by the loop. State whether gameplay implementation
actually started, citing session and first-write proof. Do not emit steady `IDLE`,
repeat only held-task summaries, invent a task, weaken acceptance, or restart
`ops-stuck-resource-20261011`. The C1 read/write-coupling proposal remains separately
held; its own guard failure is not a fleet-wide blocker.

Keep Muse/Craig scopes, Shuto frozen, NEON paused, all failed acceptance gates and
auth/security denials. No external-agent contact, Actions, deployments, paid
services, credential changes, merges or destructive deletion. Deployment requires
Craig's explicit request; ordinary source pushes still require trigger inspection.
These repository prompts do not update a saved automation or grant tools permission.
